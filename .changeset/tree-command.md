Added the experimental `tree` command: it prints an overview of an API description as a tree — its servers, every tag and webhook down to their individual operations, and component sections — and lets you drill into one tag, path, webhook, operation, component, or file with `--tag`, `--path`, `--webhook`, `--operation`, `--component`/`--name`, and `--file`, with every result attributed to the file that defines it.
`--operations` and `--webhooks` list the whole API surface, each entry already carrying its own typed one-hop `refs` and `usedBy`; `--used-by` runs impact analysis (which operations and components depend on a selection, including everything a whole file defines); `--with-deps` appends an operation's or component's transitive `$ref` closure. An operation or component selection renders as a tree too — coordinates, then `refs`/`usedBy`/`deps` as branches — with no raw source in the terminal output.
`--format=json` prints the same selection as machine-readable data — stable ids, JSON pointers, source files, line ranges, summaries, and (with `--with-deps`) raw source, all taken from the description itself; `--files` shows the file-level `$ref` graph, optionally filtered to one file's neighborhood with `--file`.
`--format=ai` is the agent format, and it's plain text, not JSON: listing views (`--tag`, `--path`/`--webhook`, `--operations`, `--webhooks`, `--component`, a `--file` card's `defines`, and `--find`) print one line per entry with `L<start>` coordinates instead of a JSON array; an operation or component card prints its body as one line of compact JSON under a `--- json` heading — top-level `x-*` vendor keys folded to an `omitted` marker with their own coordinates, and raw YAML under a `--- yaml` heading instead when the content doesn't parse — and, with `--with-deps`, the transitive `$ref` closure under `--- deps` as compact schema signatures — required fields, types, enums, and `$ref` targets — instead of raw YAML, with anything more than two `$ref` hops away listed as a bare id under `deeper` instead of a body.
Added `--find=<terms>`, a standalone search across the whole description: it ranks operations (including webhook operations) and components by how many terms hit their path, id, name, summary, or description, so an agent can narrow down a candidate without listing a whole tag or section first. It works in all three formats and doesn't combine with the typed selectors, `--used-by`, or `--with-deps`.
Added `--pointer=<json-pointer>`, a standalone selector that navigates by a raw JSON pointer straight from a `$ref` value or lint output: a pointer to a component or operation routes to the same card its typed selector would; a pointer that lands on a container boundary — the document root, `paths`, `webhooks`, one component section, or one path — routes to the same bounded listing its typed selector equivalent would, instead of dumping that whole subtree; and any deeper pointer returns a pointer card with its own coordinates and body, its `refs`, and the nearest indexed ancestor (with a `usedBy` count and a ready `--pointer` hint) for `--used-by`/`--with-deps` to combine with instead — capped at 64 KB like `--with-deps`, with a `truncated` marker past that.
The underlying engines live in `@redocly/openapi-core`'s new `api-graph` module (`analyzeApi`, `buildOverview`, `buildOperationCard`, `buildUsedByReport`, `buildFileCard`, `findMatches`).
